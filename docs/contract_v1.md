## 1. 受け渡しの全体

| 向き | もの | 形 |
|---|---|---|
| ナビ → Pro | 野帳のひな形 | ファイル（.json）または リンク（`pro.html#tpl=<符号>`）。2. の形 |
| Pro → ナビ（成績書ナビ・Rの雛形） | 調べた結果 | CSV（UTF-8・BOM付き）。7. の形 |

- ナビは Pro がなくても完結する。Pro に送る通信はない（リンクの `#` より後ろはサーバーへ送られない）
- 知らないキーは、受け取る側が捨てても害がないように作る（8.）

## 2. ひな形の形

```json
{"app":"koe-yacho-v2-template","v":1,"ver":"試験設計ナビ 生物工学版 ver. 2.4（YYYY-MM-DD）","name":"…",
 "S":{"name":"…","items":[…],"ts":true,"dir":"row","outFmt":"long","plan":{…}},
 "list":[{…},…],
 "gen":{"rows":[…]},
 "fold":{"by":[…],"open":"first","alt":[[…]]},
 "meta":{"contract":1,"src":"shiken-navi-bio","srcVer":"2.4","design":"0a1b2c3d","made":"YYYY-MM-DD","survey":"A","idCol":"line"}}
```

| キー | 置き場所 | 中身 | 受け取れる Pro |
|---|---|---|---|
| app・v・ver・name | 一番上 | `"koe-yacho-v2-template"`・`1`・作ったアプリの版・ひな形の名前 | すべて |
| S | 一番上 | 調査の設定。Pro の TPL_KEYS にあるキーだけ（知らないキーは捨てる） | すべて |
| list | 一番上 | 個体リスト（事前入力の列の値。1要素＝1行）。上限 5,000 行 | すべて |
| meta | **一番上**（3.） | 作った元の情報 | 4.9.9 から保持 |
| gen | 一番上（5.） | 個体リストの作り方 | 4.9.12 から |
| fold | 一番上（6.） | 行のまとめ方 | 4.9.13 から |

**決まり：ひな形に足すキーは、S の中ではなく一番上に置く。** S は「調査の設定」（Pro が自分で作るひな形にも出る）、一番上は「このひな形がどこから来たか・どう広げるか」。受け取った Pro は、残すものを S の中に持つ（`S.meta`・`S.fold`）。

## 3. meta（Q-1 の決定）

### 3.1 置き場所
- **渡す形**：ひな形の一番上の `meta`
- **Pro の中の持ち方**：受け取ったら `S.meta` に入れる。バックアップ・端末の保存は S ごとなので、そのまま持ち回る
- **Pro が共有するとき**（tplBuild）：`S.meta` があれば、ひな形の一番上の `meta` に出す（S の中には出さない）
- 受け取るときに一番上に `meta` がなく `S.meta` があれば、それを使う（念のための読み方。作る側は使わない）

### 3.2 キー
| キー | 型 | 中身 | 必須 |
|---|---|---|---|
| contract | 数 | この契約の版。v1 は `1` | ○ |
| src | 文字 | 作ったアプリ：`"shiken-navi"`（一般版）・`"shiken-navi-bio"`（生物工学版） | ○ |
| srcVer | 文字 | 作ったアプリの版（例 `"2.4"`） | ○ |
| design | 文字 | 設計のID（8桁の16進、小文字）。設計ファイルの `id` と同じ。ないときは `""` | ○ |
| made | 文字 | 作った日（YYYY-MM-DD） | ○ |
| survey | 文字 | どの表か。一般版は表の記号、生物工学版は表が1つなので `"A"` | ○ |
| idCol | 文字 | 個体（区・系統）を表す列の id。生物工学版は `"line"`（系統＝遺伝子型） | ○ |
| そのほか | 文字・数・真偽 | 作った側が足してよい（例 生物工学版の `rows`＝行の数）。**Pro は知らないキーも捨てずに残す** | ― |

### 3.3 Pro が受け取るときの整え方
- `meta` が普通のオブジェクトでなければ、無いものとする
- キーは `^[A-Za-z][\w-]{0,31}$` の形だけ、30個まで。値は 文字（200字まで）・有限の数・真偽だけ（入れ子・配列は捨てる）
- `design` は `^[0-9a-f]{8}$` でなければ `""` に、`made` は YYYY-MM-DD でなければ `""` にする
- 調査の設定を Pro で変えても、`S.meta` は変えない（設計との違いは、成績書ナビが列を突き合わせて見つける）

## 4. 項目（items）と id

- id の形：`^[\w-]{1,40}$`（Pro の tplSanitize と同じ）。1つのひな形の中で重ねない
- 項目の名前は、Pro が自分で付ける見出し（`調査日`・`No.`・`状態`・`除外日`・`理由`）と重ねない
- 事前入力（`role:"id"`）と記録する項目（`role:"meas"`）の区別、種類（num・text・choice・date・multi・count）、`dec`・`step`・`options`・`allow`・`only`・`call` は Pro 4.9.8 の tplSanitize のとおり

### 4.1 そろえる id（両方のナビで同じ意味に使う）
| id | 意味 |
|---|---|
| plot | 区番号（一般版） |
| block | ブロック・反復（一般版） |
| sample | 区・系統の中の番号（果実番号・株・シャーレ）。**生物工学版の株・シャーレもこの id**（名前は「株」「シャーレ」のまま） |
| pop | 集団 |
| line | 系統（生物工学版。`meta.idCol`） |
| kubun | 区分（系統／対照） |
| batch | 接種回・ロット（生物工学版） |
| grp・cross | 群・交配組合せ（生物工学版、交配の予測の検証） |
| p_seed・p_pollen | 種子親・花粉親（文字。空欄で渡す） |
| plate | プレート・泳動のまとまり（文字。空欄で渡す。判定表） |
| judge_a・judge_b | 2つの判定（選ぶ。判定表、一致の試験） |
| type | 型（選ぶ。判定表、分離比の試験） |

- 形質の id は、ナビ側の辞書にある名前だけ固定する（生物工学版：発病度 `dis_score`、病斑数 `lesion`、枯死 `dead`、発病 `dis`、発芽 `germ`、開花までの日数 `flw_days`〔起きた日の列は `flw_date`〕、硬度 `firm`、糖度 `brix`、果実重 `fwt`、測定値 `val`、計数 `cnt`）。辞書にない名前は `t1` など、年をまたいで同じになることは保証しない
- 段階スコアは数値・小数0、測った数値は小数1で渡す（Pro で直せる）

## 5. 個体リストの作り方 gen（Q-3 の決定）

ナビ生物工学版 ver. 2.3 が出している形を、そのまま契約の形にする。

```json
"gen":{"rows":[
  {"each":[{"id":"pop","seq":{"from":1,"to":2,"fmt":"P-{n:2}"}},
           {"id":"line","seq":{"from":1,"to":150,"fmt":"L-{n:3}","cont":true}},
           {"id":"sample","seq":{"from":1,"to":3}}],
   "set":{"kubun":"系統"}},
  {"each":[{"id":"line","vals":["抵抗性対照","罹病性対照"]},{"id":"sample","seq":{"from":1,"to":3}}],
   "set":{"kubun":"対照","pop":"—"}}]}
```

| キー | 中身 |
|---|---|
| rows | 作り方の並び。上から順に行を作る |
| each | 入れ子の繰り返し（先頭が外側）。1つの要素は `seq` か `vals` のどちらか |
| seq | `from`・`to`（整数、from ≤ to）。`fmt` があれば `{n}`（そのまま）または `{n:k}`（k 桁に0でそろえる）を番号に置き換えた文字、なければ数 |
| cont | `true` なら、外側が変わっても番号を続ける（同じ rows の要素の中で、id ごとに from から通しで数える。rows の要素が変われば数え直す） |
| vals | 値の一覧（文字か数） |
| set | その作り方の行すべてに入れる値（id → 値） |

- **gen と list の両方があるとき、gen を知っている Pro は gen だけから行を作り、list は使わない。** list は gen を知らない古い Pro のための写しで、作る側は「gen を広げた行 ＝ list」を1行ずつ一致させる（ナビは検査で確かめる）
- 広げた行の上限：**4.9.12 では今と同じ 5,000 行**。超えるときは受け取らず、「◯行になります。上限は 5,000 行です」と知らせる。上限を上げるのは、行のまとめ（6.）が入って、数千行を描かずに扱えるようになってから（4.9.13 で決める）
- Pro が受け取るときの整え方：rows は 100,000 まで（ロットごとの対照では、ロット×集団の数だけ並ぶ）、each は8段まで、seq の from・to は 0〜10,000,000 の整数、fmt は 40字まで・`{n}` か `{n:k}`（k は 1〜6）が1つだけ、vals は値が100字まで。事前入力の項目にない id は、繰り返しの回数はそのままで値を入れない。set も項目にある id だけ。**形が読めない gen は無いものとして list を使う**。読めて行が上限を超えるときは、行の数を知らせて受け取らない
- 行の順は、作り方の順のまま（Pro は並べ替えない）

## 6. 行のまとめ方 fold（Q-2 の決定）

- **Pro 4.9.13 で入れる**（gen の次）。キーと置き場所は、ナビ ver. 2.3 が出している形のまま：ひな形の一番上の `fold`、Pro の中では `S.fold`
```json
"fold":{"by":["pop","line"],"open":"first","alt":[["kubun"],["batch"]]}
```
| キー | 中身 |
|---|---|
| by | まとめる列の id（上の段から、2つまで）。どれも事前入力の項目 |
| open | 最初に開いておくまとまり：`"first"`（先頭だけ）／`"none"`（全部閉じる） |
| alt | Pro の画面で切り替えられるほかのまとめ方の候補（任意） |

- まとめ方は見せ方だけ。**CSV の中身・列・行の順・個体の数は変えない**
- 4.9.13 の中身（入力の順番・音声で呼んで開く・見出しの数・行の上限）は、Pro 側で方針を出して決める（ナビ側の希望は shiken-navi-src の docs/53 の 2.）

## 7. CSV

### 7.1 見出し
- 見出しは項目の名前。Pro が付ける列：`調査日`（その日の表・縦持ち）、`No.`（通し番号を付ける設定のとき）、`状態`、野帳型は `除外日`・`理由`
- 野帳型（横持ち）の記録する列は `名前_YYYY-MM-DD`

### 7.2 見出しに id を付ける設定（Pro 4.9.11。Q-5 の決定）
- 設定がオンのとき、**項目の列だけ**、見出しの末尾に「半角スペース＋`[id]`」を付ける：`果実重 [fwt]`。野帳型は `果実重_2026-12-01 [fwt]`（末尾に付ける形をそろえる）
- Pro が付ける列（`調査日`・`No.`・`状態`・`除外日`・`理由`）には付けない
- 付けるのは「その日の表」「縦持ち（R用）」「野帳型」の CSV と、同じ表の Excel。「全調査日の一覧」「集計」の書き出しは画面に見えるとおりで、付けない
- 設定の初期値はオフ（今までと同じ CSV）。設定は S の `csvIds`（真偽）に持ち、ひな形でも渡せる（TPL_KEYS に足す）
- 読む側（ナビの R の雛形・成績書ナビ）は、**見出しの末尾の ` [id]` を外してから**名前で読む。R では次の1行：
```r
names(d) <- sub(" \\[[A-Za-z0-9_-]{1,40}\\]$", "", names(d))   # 見出しの末尾の [id] を外す（Pro の設定がオフでもそのまま動く）
```
- Pro の「表を読み込む」（CSV・Excel から作る）も、見出しの末尾の ` [id]` を外して名前で突き合わせ、id が項目の id と合えば id で突き合わせる

### 7.3 ファイル名（Pro 4.9.10）
- `S.meta.design` があるとき、調査の名前のあとに `_<設計のID>` を足す：`<調査名>_<設計のID>_<YYYY-MM-DD>.csv`、`<調査名>_<設計のID>_全調査日_縦持ち_<YYYY-MM-DD>.csv` など（CSV と Excel の書き出しすべて）
- `S.meta.design` がないときは今までと同じ

### 7.4 基準日（Q-4 の決定）
- **v1 では、基準日（接種日・播種日・置床日）の列は、Pro も持たず、ナビもひな形の項目として渡さない**
- 理由：基準日は試験（またはロット）ごとに1つの値で、個体の行ごとに入れると調査の手間が増える。ロットごとに基準日が違う設計の扱いは解析の中身に関わるので、ナビ側で統計の判断を経てから決める
- ナビの R の雛形は今のまま、読み込みの行で利用者が基準日を書く（書かないと止まる形）
- 次の版の候補：`meta` か台帳（β）に基準日を持つ形（12. の「v2 の候補」）

## 10. Q-1〜Q-5 の決定（2026-11-25）

両方のソース（Pro 4.9.8 の tplBuild・tplSanitize・CSV の書き出し、ナビ生物工学版 ver. 2.3 の link.js）を見て決めた。

| # | 問い | 決定 | 理由 |
|---|---|---|---|
| Q-1 | meta の置き場所 | 渡すときは一番上、Pro の中では `S.meta`（3.1） | ひな形の一番上は app・v・ver・name と同じ「このファイルの情報」の場所。ナビはすでに一番上に出している。S は Pro が自分で作るひな形にも出る「調査の設定」で、TPL_KEYS に meta を足すと、Pro が作ったひな形にもナビの meta がそのまま混ざる |
| Q-2 | 行の折りたたみ fold | Pro 4.9.13（gen の次）。キー・置き場所はナビ ver. 2.3 の形（6.） | 画面の作りが一番大きい変更で、行の上限の見直しとも絡む。gen（行を作る）を先に入れて、まとめ（行を見せる）をその上に作る |
| Q-3 | gen の形 | ナビ ver. 2.3 の形のまま（5.）。gen があれば list は使わない | 形がすでに動いていて、ナビの検査（gen を広げた行 ＝ list、2,363件）がある。list を足すと行が二重になるので、list は古い Pro のための写しと決める |
| Q-4 | base_date | v1 では列を持たない（7.4） | 行ごとに入れる手間。ロットごとに違う基準日は解析の中身に関わる |
| Q-5 | 見出し `名前 [id]` | 末尾に「半角スペース＋[id]」、Pro の列には付けない。読む側は末尾を外す（7.2） | 外す1行で、設定のオン・オフどちらの CSV も同じに読める |
